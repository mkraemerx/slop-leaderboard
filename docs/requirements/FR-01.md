# FR-01 Template & Participant Repository Tracking

The system is configured with one template repository and tracks all
participant repositories derived from it. A participant repository represents
one author's workspace.

Participant repositories are **clones of a template repository**, not GitHub
forks. They are bundled in a single organisation. Because they are clones, the
platform exposes no fork/template lineage on the clone itself
(`template_repository` is null, `fork` is false) — discovery therefore works
via the organisation, not via the fork API.

**Acceptance criteria:**

- The system is configured with the template repository URL, the organisation
  that holds the participant repositories, and a platform API token (GitHub).
- The template repository acts as the root for analysis: commits reachable in
  the template are excluded from author attribution and from the leaderboard.
- Participant repositories are discovered automatically by listing the
  organisation's repositories and adding every repository that is not the
  template itself, not flagged as a template (`is_template`), and not on a
  configurable exclusion list (for infrastructure repos such as build images
  or shared config).
- Repositories can also be added manually by pasting URLs into a text area,
  one URL per line. Manual entries are merged with discovered ones; duplicates
  are ignored.
- A discovered or manually added repository whose history does not share the
  template's root commit is flagged, so an unrelated repo accidentally placed
  in the organisation does not silently pollute the leaderboard.
- The tracked list shows each repository with its owner name, sync status, and
  when it was last analysed.
- The repository management view provides a **"Clear all"** action that removes
  every tracked participant repository, all its analysis data, and its local
  clone, so the installation can be reused for a new setup. The template and
  organisation configuration can then be set anew.
- Author identity data (aliases and the ignore list) is preserved across a
  "Clear all", since it is cohort-independent; clearing it is a separate,
  explicit action.

**Notes:**

- Discovery via the organisation replaces the previous fork-API discovery.
  The shared-root-commit check is the authoritative link between template and
  participant repository; the organisation membership and naming convention
  are the discovery mechanism.
